\begin{frame}{Partitionnement par tourniquet}

    \begin{definitionbox}
        Le \textbf{partitionnement par tourniquet} (\textit{round-robin partitioning} en anglais) est une méthode de distribution des données où chaque enregistrement est successivement assigné à l'une des partitions disponibles de \textbf{manière cyclique}, assurant une répartition équilibrée de la charge
    \end{definitionbox}

    \pause

    \begin{examplebox}{Exemple}
        \textbf{Comment assigner une donnée $i$ à un n\oe{}ud $n_j$ ?}

        La donnée située à l'index $i$ sera assignée au n\oe{}ud d'index $j$ noté $n_j$ avec \textit{$n_j$ = i mod n} où $n$ est le nombre de n\oe{}uds.
    \end{examplebox}

\end{frame}

\begin{frame}{Avantages et inconvénients du partitionnement par tourniquet}

    \prosbox{
        \textbf{Lecture} : bonne répartition des données, possibilité de paralléliser les lectures sur plusieurs partitions

        \textbf{Écriture} : écritures réparties uniformément entre les partitions, évitant les partitions surchargées et les goulots d'étranglement
    }

    \pause

    \consbox{
        \textbf{Lecture} : une recherche sur une valeur précise nécessite généralement de parcourir toutes les partitions

        \textbf{Écriture} : pas de regroupement logique des données, ce qui peut compliquer la gestion et l'accès à des ensembles de données liés
    }

\end{frame}

    \begin{noteblock}
        Le partitionnement par intervalle est souvent utilisé pour les données temporelles, où les enregistrements sont répartis en fonction de la date ou de l'heure de création.
    \end{noteblock}

\begin{frame}{Avantages et inconvénients du partitionnement par intervalle}

    \prosbox{
        \textbf{Lecture} : très performant pour les recherches par intervalle, car elles accèdent uniquement à la partition pertinente

        \textbf{Écriture} : efficace lorsque les écritures sont réparties sur plusieurs intervalles
    }

    \note{Avantage d'écriture : particulièrement utile pour les données temporelles ou séquentielles}

    \pause

    \consbox{
        \textbf{Lecture} : une requête qui ne correspond pas au critère d'intervalle peut nécessiter de parcourir plusieurs partitions

        \textbf{Écriture} : risque de créer une partition déséquilibrée si les nouvelles données sont concentrées dans un même intervalle
    }

\end{frame}

\begin{frame}{Partitionnement par clé}

    \begin{definitionbox}
        Le \textbf{partitionnement par clé (ou liste)} (\textit{key partitioning} ou \textit{list partitioning} en anglais) répartit les données en fonction de la valeur d'une ou plusieurs colonnes spécifiques, qui sont appelées les clés de partitionnement.
    \end{definitionbox}

    \pause

    \begin{noteblock}
        Le partitionnement par clé est souvent utilisé pour les données qui peuvent être regroupées en catégories distinctes, telles que les données géographiques, les catégories de produits, etc.
    \end{noteblock}
\end{frame}

\begin{frame}{Avantages et inconvénients du partitionnement par clé}

    \prosbox{
        \textbf{Lecture} : accès rapide aux partitions correspondant à une valeur ou à un groupe de valeurs

        \textbf{Écriture} : permet de contrôler précisément la répartition des données
    }

    \note{Avantage d'écriture : Les opérations d'écriture sont distribuées de manière équilibrée si la distribution des clés est uniforme, évitant ainsi les goulots d'étranglement.}

    \pause

    \consbox{
        \textbf{Lecture} : les requêtes portant sur plusieurs groupes de valeurs peuvent nécessiter de lire plusieurs partitions

        \textbf{Écriture} : risque de déséquilibre si certaines valeurs sont beaucoup plus fréquentes que d'autres (skewed distribution)
    }

\end{frame}

\begin{frame}{Partitionnement par hachage}

    \begin{definitionbox}
        Le \textbf{partitionnement par hachage} (\textit{hash partitioning} en anglais) distribue les données en fonction du résultat d'une fonction de hachage appliquée à une ou plusieurs colonnes.
        $$f(x) = y$$
        avec $x$ la clé de partitionnement et $y$ le n\oe{}ud de destination.
    \end{definitionbox}

    \pause

    \begin{noteblock}
        Il existe de nombreuses fonctions de hachage comme xxHash ou MurmurHash (utilisé par Memcached et Apache Cassandra) qui permettent de générer un hachage unique pour chaque valeur d'entrée.
    \end{noteblock}

    \note{
        Le partitionnement par hachage est souvent utilisé pour répartir uniformément les données et éviter les déséquilibres de charge.
        Avec le partitionnement par hachage, les données sont réparties de manière aléatoire, mais déterministe.

    }

\end{frame}

\begin{frame}{Avantages et inconvénients du partitionnement par hachage}

    \prosbox{
        \textbf{Lecture} : très efficace pour les recherches portant sur une clé exacte

        \textbf{Écriture} : distribution généralement uniforme des données entre les partitions, ce qui équilibre la charge
    }

    \pause

    \consbox{
        \textbf{Lecture} : peu efficace pour les recherches par intervalle, car les valeurs proches peuvent être réparties dans des partitions différentes

        \textbf{Écriture} : la modification du nombre de partitions peut nécessiter une redistribution importante des données
    }

    \note{
        \textbf{Question} : Que pensez-vous de ces différentes stratégies de partitionnement ?

        \textbf{Question} : Quelle est la meilleure stratégie de partitionnement pour la lecture et l'écriture des données ?

        \begin{itemize}
            \item Le partitionnement par tourniquet est simple et efficace pour équilibrer la charge d'écriture, mais il ne prend pas en compte les caractéristiques des données.
            \item Le partitionnement par intervalle est efficace pour les requêtes par plage, mais peut entraîner des déséquilibres si les données sont concentrées dans certaines plages.
            \item Le partitionnement par clé permet de regrouper les données par catégories, mais peut également entraîner des déséquilibres si certaines catégories sont plus fréquentes que d'autres.
            \item Le partitionnement par hachage répartit les données de manière uniforme, mais peut rendre les recherches par plage moins efficaces.
        \end{itemize}
    }

\begin{frame}{Résumé des performances}

    \begin{table}
        \centering
        \begin{tabular}{|l|l|l|}
            \hline
            \textbf{Technique} & \textbf{Lecture} & \textbf{Écriture} \\
            \hline
            Tourniquet & \textcolor{customred}{\textbf{Faible}} & \textcolor{customgreen}{\textbf{Très bonne}} \\
            Intervalle & \textcolor{customgreen}{\textbf{Très bonne}}* & \textcolor{orange}{\textbf{Variable}} \\
            Clé/liste & \textcolor{customgreen}{\textbf{Très bonne}}* & \textcolor{orange}{\textbf{Bonne}} \\
            Hachage & \textcolor{customgreen}{\textbf{Bonne}}* & \textcolor{customgreen}{\textbf{Très bonne}} \\
            \hline
        \end{tabular}
    \end{table}

    * surtout lorsque la requête utilise le critère de partitionnement.

    \note{

        \begin{columns}[t,onlytextwidth]
            \begin{column}{.49\textwidth}
                \textbf{Lecture}
                \small
                \begin{itemize}
                    \item \textbf{Partitionnement par intervalle} $\rightarrow$ \textcolor{customgreen}{\textbf{Très bon}} pour les requêtes par plage
                    \item \textbf{Partitionnement par clé/liste} $\rightarrow$ \textcolor{customgreen}{\textbf{Très bon}} pour les recherches sur une valeur précise
                    \item \textbf{Partitionnement par hachage} $\rightarrow$ \textcolor{customgreen}{\textbf{Bon}} pour les recherches par clé exacte
                    \item \textbf{Partitionnement par tourniquet} $\rightarrow$ \textcolor{customred}{\textbf{Moins bon}} pour les recherches ciblées
                \end{itemize}
            \end{column}
            \hfill
            \begin{column}{.49\textwidth}
                \textbf{Écriture}

                \small
                \begin{itemize}
                    \item \textbf{Partitionnement par hachage} $\rightarrow$ \textcolor{customgreen}{\textbf{Très bon}}, distribution généralement uniforme
                    \item \textbf{Partitionnement par tourniquet} $\rightarrow$ \textcolor{customgreen}{\textbf{Très bon}}, distribution uniforme par construction
                    \item \textbf{Partitionnement par clé/liste} $\rightarrow$ \textcolor{orange}{\textbf{Bon}}, mais dépend de la répartition des valeurs
                    \item \textbf{Partitionnement par intervalle} $\rightarrow$ \textcolor{customred}{\textbf{Variable}}, risque de surcharge sur certaines partitions (même intervalle)
                \end{itemize}
            \end{column}
        \end{columns}

        \vspace{0.2cm}

        \textbf{Lecture} : Intervalle / Clé-Liste $>$ Hachage $>$ Tourniquet

        \textbf{Écriture} : Hachage ≈ Tourniquet $>$ Clé-Liste $>$ Intervalle

        \vspace{0.2cm}

        Le choix de la stratégie dépend du type de requêtes majoritaires (lecture ou écriture), de la distribution des données, et des besoins spécifiques de l'application en termes de performance.

    }

\end{frame}
